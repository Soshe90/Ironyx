# Setup — turning this overlay into a runnable project

This repository is a **source overlay**. It contains `lib/`, `test/`,
`integration_test/`, `docs/`, CI config and `pubspec.yaml` — but no
`android/`, `ios/` or `web/` directories, because those are generated by
the Flutter tool and must match your local SDK.

## 1. Generate the platform scaffolding

```bash
flutter create \
  --org com.yourdomain \
  --project-name ironyx \
  --platforms=android,ios,web \
  --description "Offline-first workout tracker" \
  ironyx
```

> `--org` becomes the Android `applicationId` and the iOS bundle
> identifier. It is effectively permanent once you have submitted to a
> store. Use a reverse-domain you control.

## 2. Overlay this source on top

```bash
cp -r ironyx-overlay/. ironyx/
cd ironyx
rm -f lib/main.dart.bak test/widget_test.dart   # remove the counter sample
```

The overlay replaces `lib/main.dart`, `pubspec.yaml`,
`analysis_options.yaml`, `.gitignore` and `README.md`. Delete the generated
`test/widget_test.dart` — it tests the counter app that no longer exists and
will fail.

## 3. Refresh dependency versions

The versions in `pubspec.yaml` are a **floor, not a recommendation**. They
were written against a known-good set and will be stale by the time you read
this. Refresh them:

```bash
flutter pub get
flutter pub upgrade --major-versions
```

Then read the diff. Major-version bumps in `go_router`, `riverpod` and
`drift` have all carried breaking changes historically.

## 4. Generate code

```bash
dart run build_runner build
```

**Required before the first compile.** `*.g.dart` files are gitignored, so
`themeModeControllerProvider` does not exist until you run this. Expect a
wall of "undefined name" errors if you skip it.

## 5. Verify

```bash
dart format .
flutter analyze --fatal-infos --fatal-warnings
flutter test
flutter run --dart-define-from-file=supabase.json
```

## 6. Supabase credentials (optional accounts)

`SupabaseConfig` reads `SUPABASE_URL` and `SUPABASE_ANON_KEY` via
`String.fromEnvironment`, which resolves at **compile time** (ADR-8). Omit
them and the app still runs — storage is local — but auth is swapped for
`DisabledAuthService` and Settings shows "Accounts unavailable".

```bash
cp supabase.example.json supabase.json   # gitignored; paste your real values
scripts/build_android.sh run             # or apk / bundle / install
```

`scripts/build_android.sh` and the `.vscode/launch.json` configurations both
pass `--dart-define-from-file=supabase.json` so the flag cannot be forgotten.

## Known version-sensitive spots

I could not compile-check this code, so these are the places most likely to
need a small edit against your SDK. Each is isolated to one file.

| Symbol | File | Note |
|---|---|---|
| `Color.withValues(alpha:)` | `app_theme.dart`, `summary_card.dart` | Requires Flutter 3.27+. On older SDKs use `withOpacity`. |
| `ColorScheme.surfaceContainer*` | `app_theme.dart` | Requires Flutter 3.22+. Older SDKs use `surfaceVariant`. |
| `WidgetStateProperty` | `app_theme.dart` | Renamed from `MaterialStateProperty` in 3.22. |
| `StatefulShellRoute.indexedStack` | `app_router.dart` | Stable since go_router 10, but the `builder` signature changed in 9→10. |
| `@Riverpod(keepAlive: true)` | `theme_mode_controller.dart` | Class-based syntax is stable across riverpod 2.x and 3.x. The function-based `Ref` typedef is not — avoid it. |
| `SharedPreferences.getInstance` | `main.dart` | If you move to `SharedPreferencesAsync`, the provider override in `main.dart` is the only place to change. |

If something does not compile, fix it in place rather than working around
it — and if the fix contradicts `docs/ADR.md`, update the ADR in the same
commit so the two never disagree.

## What is actually built

**M0–M2 complete, M3 source-complete, M4 core complete.** Specifically:

- Material 3 theme, light and dark, with hand-tuned neutral dark surfaces
- Spacing / radius / duration constants, tabular-figure number styles
- `go_router` with five branches plus root-level detail routes
- `NavigationBar` on compact, `NavigationRail` at ≥768dp
- Shared widgets: `AppCard`, `EmptyState`, `ErrorView`, `LoadingShimmer`, `FilterChipGroup`
- Dashboard with five placeholder cards, each owning its loading/error state
- Settings with a persisted theme preference
- Haptics service with a web no-op (ADR-6)
- Weight, duration and date formatters with kg-only storage (ADR-1)
- Drift schema (all tables), DAOs, exercise seed asset and seeder, database providers
- Library search/filter/detail UI over the seeded exercise catalogue
- Tracker: workout draft models, active-workout and edit notifiers, history/detail/edit screens and routes
- Timer: wall-clock engine, quick-start and custom presets, active-session UI, capability services (audio/notifications/wakelock), permission flow and denial fallback
- Unit and widget tests (analyzer-clean and passing locally)
- CI running format, codegen, analyze, test, APK and web builds

This overlay has been validated locally with `flutter pub get`,
`build_runner`, `flutter analyze --fatal-infos --fatal-warnings`, `dart format`,
and `flutter test` — all green.
